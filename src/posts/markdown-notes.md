## 先说清楚问题

一篇技术笔记可以先交代三个信息：遇到了什么现象，希望得到什么结果，以及已经尝试过什么。读者有了这些背景，才知道后面的解决方法是否适用于自己。

这篇文章用于展示正文排版，后续会换成张峰瑜的正式技术博客。

## 让结构帮助阅读

较长的内容可以按「问题背景、解决过程、验证结果」组织。每个小标题都对应一个具体的问题，目录会自动收录这些标题。

> 留下推理过程，通常比只留下最终答案更有价值。

使用列表适合表达并列的信息；需要执行顺序时，再使用有序列表。不要把所有段落都变成条目，完整的句子也能帮助读者理解上下文。

## 给代码一个上下文

下面是一段用于展示排版的 JavaScript 示例：它把学习主题转换成便于阅读的清单。

```js
const topics = ['理解问题', '动手验证', '整理笔记'];
const notes = topics.map(topic => `今天的航线：${topic}`);
console.log(notes.join('\n'));
```

介绍代码时，先说明输入和预期输出，再解释关键部分。较长的代码可以横向滚动，不会把手机页面撑开。

## 记录验证结果

一个方法是否可用，需要有对应的验证。可以记录测试条件、实际结果，以及仍然没有解决的问题。

| 记录项 | 建议内容 |
| --- | --- |
| 输入 | 使用了哪些示例或数据 |
| 过程 | 执行了哪些操作 |
| 输出 | 实际观察到的结果 |
| 边界 | 哪些条件尚未覆盖 |

下次再遇到类似问题，这些细节会成为更可靠的路标。
